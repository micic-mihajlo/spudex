### Investigation

1. State the question in checkable terms.
2. Read the authoritative sources first.
3. Trace from entry point to outcome.
4. Separate facts, inferences, and unknowns.
5. Do not change code unless the user explicitly asks for a fix.

No PR. No `architect` unless the investigation becomes implementation work.

Reply with the answer first, then evidence, open questions, and recommended next steps.
